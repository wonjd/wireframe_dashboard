화면 생성 파이프라인

본부장이 자연어 PRD를 넣으면 상세한 HTML 화면이 나오고, 마음에 들 때까지 직접 돌리다가 개발자에게 넘긴다. 기존 코드베이스와 DB에서 뽑은 자산 위에서만 화면이 생성되므로, 몇 번을 갈아엎어도 톤과 구조가 흔들리지 않는다.

결정 사항

  1. 저장은 파일.벡터는 프로젝트가 늘고 추출로 못 덮는 자유 질의가 생길 때, 그때도 생성이 아니라 탐색 쪽에 붙인다. 파일은 git diff에 보이고 인덱스는 조용히 낡는다.
  2. 추출층과 규칙층을 나눈다.추출은 사실(“색이 41개 있다”), 규칙은 판단(“그중 5개만 쓴다”). 재추출이 판단을 덮으면 안 된다.
  3. DB는 반복 루프 밖 1회.스키마 덤프가 아니라 카디널리티 · 코드값 개수 · 규모까지 판정해서 넘긴다. 1:N을 1:1로 그린 오류는 본부장이 못 잡는 유일한 종류다.
  4. 생성 단위는 화면 1개.잠금과 화면 단위 재생성은 나중에 붙일 수 없다 — 생성부를 만들 때 같이 넣어야 한다. 뷰어 UI는 마지막이어도 된다.
  5. 파이프라인 코드는 wireframe_dashboard.Hermes에는 cli를 부르는 껍데기 툴만 등록한다 — 채팅과 폼이 완전히 같은 경로를 타야 한다.
